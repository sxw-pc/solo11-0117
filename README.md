# 渔获上岸核秤台

港口离线登记航次与实物箱组、秤具校准与复秤、分物种配额放行。各输入原始字节及哈希保留在 SQLite，身份冲突拒绝覆盖；可信净重才占配额，重复导入和重复放行不会重复占额。

运行：`python -m pip install . --no-deps --no-build-isolation`，`python -m landingweigh demo`，`python -m pytest -q`。三个业务入口是 `trip-import`、`weigh-import`、`quota-import`，均接受 `--db` 和 `--file`。正常与冲突输入在 fixtures；`report` 输出来源、航次、箱组、秤票、配额和放行证据。演示数据仅为合成离线数据。

许可清单限定航次、物种及时间。现场 `inspect-import` 能把箱组核定物种改为许可内物种，因而改用另一配额；不在许可内的物种会扣留。复秤冲突后，`weigh-adjudicate` 可引用仍具有效校准的票据形成新可信重量，后到票据会使旧裁定失效。跨船 `quota-transfer` 需要来源船的授权额度和未用余额，转移后重算放行。每次放行状态变化写入 release_event；`demo-decisions` 展示物种复核、配额转移、复秤争议和裁定的完整链路。

## 时钟校对单

靠港记录、启航记录和许可证不一定出自同一台钟。`trip-import` 的 `clock_sheets` 接受码头离线采录的有凭据校对单：须写明签发人与签发时刻，最多四台设备、六条钟差约束；每条约束写明两台设备、校对时刻及差值上下界（秒），且每张校对单至少一台设备有相对 UTC 的签发锚点。设备偏移 o 的语义是 UTC = 钟面读数 + o；同一设备在同一航次内按同一偏移解释，许可两端的条件必须在同一组偏移解释里同时成立。全部解释都满足时航次为有效（arrived），无一满足时扣留（held），其余为待核（pending）。约束互相矛盾时整批校对证据被隔离（quarantined，留存但不参与解释），不按输入顺序取舍；与已接受证据矛盾的后到批次同样隔离。

许可证可用 `start_event`/`end_event` 分别声明起、止两端按启航（depart）或靠港（arrive）事件核验，缺省均按靠港（兼容旧行为）；准入依据取自文书。航次须以 `depart_device`/`arrive_device` 声明读数出自哪台钟，该归属与航次身份一并冻结。待核航次的箱组可登记实物与原始钟读数，但不得可信核秤或放行；后来补入的签发锚点能把待核转成有效或扣留，状态迁移写入 voyage_status_event，已有箱组和秤票的来源不会被重写。`report` 的 `voyage_clock` 展示共同可行的偏移区间、事件 UTC 区间、采用的许可事件、各条件的成立情况与阻断原因。示例见 fixtures/trip_clock_*.json：启航钟 A 与靠港钟 B 同偏移（快零至十分钟），11:55 启航、12:05 靠港，许可要求启航不早于 11:50 且靠港早于 12:00——两端各自都能在某个偏移下合格，但没有一个共同偏移使两端同时合格，航次扣留；若文书把结束条件改为启航早于 12:00，则同一航次转为待核，可由后到锚点定夺。
